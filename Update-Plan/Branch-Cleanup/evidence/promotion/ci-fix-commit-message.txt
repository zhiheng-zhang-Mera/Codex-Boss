ci: build before test so the acceptance harnesses can load

Fix the failing Desktop CI validate job. `pnpm test` ran before `pnpm run build`,
but several acceptance harnesses `require` the compiled modules under
dist-electron at module load time:

  scripts/r901-soak.cjs, scripts/closure-soak-2h.cjs,
  scripts/benchmark.cjs, scripts/acceptance-*.cjs

dist-electron is a gitignored build output (.gitignore:5), so on a fresh
checkout it does not exist yet. tests/unit/closure-terminal-logic.test.ts
spawns two of those harnesses, and with the old order the child process died
with "Cannot find module '../dist-electron/electron/commander/execution-supervisor.js'"
and exited 1 instead of its documented exit code, so two tests failed on every
CI run:

  a formal soak shorter than MIN_ACCEPTANCE_SECONDS is refused (exit 2)
    -> expected 2, received 1
  a validate-only run never claims acceptance (exit 0, qualifiesForAcceptance=false)
    -> expected 0, received 1

The scripts are correct and unchanged: their exit codes are right once the
modules they require exist. Only the step order was wrong.

Verified locally with the new order:
  pnpm run typecheck  -> exit 0
  pnpm run build      -> exit 0
  pnpm test           -> 82 files / 687 tests passed, exit 0
  pnpm run benchmark  -> exit 0

Also confirmed the two later steps do not need an interactive desktop:
electron/main.ts runs the smoke lane headless (`offscreen: isSmokeTest`,
`show: !isSmokeTest`, hardware acceleration disabled), which is how they already
pass on the windows-latest runner.

No product code, no test, and no acceptance standard was changed to obtain a
green run.
